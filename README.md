# FairShare xv6 Scheduler

FairShare is an xv6/RISC-V teaching-kernel project that compares the stock
round-robin-style scheduler with a shortest-predicted-burst policy augmented
by I/O preference and aging.  The repository also includes the Phase 4
workloads, Phase 5 captured measurements, and a small local dashboard for
exploring those existing measurements.

## Build and run xv6

Install a RISC-V cross compiler and `qemu-system-riscv64`, then run from the
repository root:

```sh
make qemu
```

This builds the kernel and filesystem image, then boots xv6 in QEMU.  Exit the
QEMU console with `Ctrl-a`, then `x`.  The FairShare test programs are
`cpubound`, `iobound`, `mixed`, and `starvation`; they are already included in
the xv6 user-program build.

## Architecture

The scheduling policy is implemented in `kernel/proc.c`, with process state
and policy constants in `kernel/proc.h`.  On each selection pass, every
runnable process receives a priority derived from its predicted CPU burst,
its CPU/I/O classification, and elapsed waiting time.  The lowest numerical
priority wins; ties retain process-table order.  Tick accounting updates CPU,
sleep, and evaluation metrics.  See [architecture_and_math.md](docs/architecture_and_math.md)
for the implemented data flow, formulas, and constants.

## Existing results

Phase 5 data is retained in `experiments/results.csv` and
`experiments/fairness.csv`; it is not regenerated by the dashboard.  The
captured workloads cover CPU-bound, I/O-bound, mixed, and starvation cases,
with Vanilla xv6 and FairShare observations.  See [results.md](docs/results.md)
for a concise summary and interpretation notes.

## Local dashboard

The dashboard reads the two existing CSV files each time its JSON endpoint is
requested.  It does not run xv6 or alter the experiment artifacts.

```sh
python -m pip install -r dashboard/requirements.txt
python dashboard/app.py
```

Open `http://127.0.0.1:5000/` in a browser.  It displays side-by-side Vanilla
and FairShare averages for response time, waiting time, turnaround time, CPU
time, context switches, and Jain's Fairness Index.  Each bar is the arithmetic
mean of all captured rows for a workload and scheduler; the fairness chart
means the existing per-repetition fairness records.
